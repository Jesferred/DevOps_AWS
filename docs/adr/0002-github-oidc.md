# 2. GitHub Actions authenticates to AWS via OIDC

Date: 2026-10-25
Status: Accepted

## Context

CI needs AWS access to plan and apply Terraform. Long-lived IAM access keys
stored in GitHub Secrets must be rotated and are a common leak vector.

## Decision

Register GitHub as an IAM OIDC identity provider. Workflows exchange a
GitHub-signed JWT for 1-hour STS credentials.

| Role        | Permissions                           | Who can assume (`sub` claim)                       |
|-------------|---------------------------------------|----------------------------------------------------|
| `gha-plan`  | `ReadOnlyAccess` + state lock objects | `repo:Jesferred/DevOps_AWS:*` (any branch, PRs)     |
| `gha-apply` | `AdministratorAccess`                 | `repo:Jesferred/DevOps_AWS:environment:production`  |

The `production` GitHub environment requires manual approval, so no change
reaches AWS without a human review of the plan.

## Consequences

- No static credentials exist anywhere.
- `gha-apply` is intentionally broad while the resource set is still growing.
  Once the stacks are stable, it will be narrowed to the actions actually used,
  generated by IAM Access Analyzer from CloudTrail history.
